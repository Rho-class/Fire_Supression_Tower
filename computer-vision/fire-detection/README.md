# Candle Flame Detection

This folder trains and runs a dedicated one-class YOLO26 detector. Its only
class is `0 = flame`. It does not control the pump, motors, or ESP32, and it
does not perform person detection. Those responsibilities remain separate.

## Environment and CUDA

Use the project virtual environment from PowerShell:

```powershell
cd computer-vision\fire-detection
.\.venv\Scripts\Activate.ps1
```

Install a CUDA-enabled PyTorch build using the command generated by the
[official PyTorch Windows selector](https://pytorch.org/get-started/locally/).
Install the remaining packages afterward:

```powershell
python -m pip install -r requirements.txt
```

The OpenCV requirement remains pinned to `4.14.0.94` to avoid an unintended
OpenCV replacement. Verify the driver and PyTorch before doing anything else:

```powershell
nvidia-smi
python -c "import torch; print('PyTorch:', torch.__version__); print('CUDA available:', torch.cuda.is_available()); print('CUDA:', torch.version.cuda); print('GPU:', torch.cuda.get_device_name(0) if torch.cuda.is_available() else 'None')"
```

Do not train if `CUDA available` is `False`. All three production scripts also
enforce this and will not silently fall back to CPU.

## Dataset

Download the candle-fire dataset in **YOLO26** format from:

<https://universe.roboflow.com/processing-workspace/candle-fire-mz13q>

Extract it so the configuration is located here:

```text
computer-vision/fire-detection/datasets/candle-fire/data.yaml
```

Before training, inspect `data.yaml`. It must contain exactly one class and
working `train` and `val` paths. The training script verifies those paths and
writes a generated configuration that normalizes the class to `0 = flame`.
The downloaded dataset and generated configuration are ignored by Git.

Future Logitech-camera training images should include small candle flames at
about 5 feet and, where practical, 10 feet. Add hard-negative images of
flashlights, red/orange objects, desk lamps, reflections, unlit candles, and
phone screens. A negative image must have a matching empty YOLO label file.

## Training

```powershell
python train_candle_yolo_cuda.py
```

Training starts from `yolo26x.pt`, uses CUDA device 0, 640-pixel images,
automatic CUDA batch sizing, mixed precision, up to 100 epochs, and early
stopping after 20 epochs without improvement. The first run normally writes:

```text
runs/candle_yolo/weights/best.pt
```

Ultralytics adds a numeric suffix for later runs rather than overwriting an
existing run. Pass the desired checkpoint to the other scripts with `--model`.

On an 8 GB RTX 5060, Ultralytics' automatic profiler may discover batch 2 but
then leave CUDA in an out-of-memory state while probing larger candidates. If
that happens, restart training with the discovered safe value:

```powershell
python train_candle_yolo_cuda.py --batch 2
```

## Webcam detection

The default model preference is `best.engine`, followed by `best.pt`:

```powershell
python detect_candle_flame.py
python detect_candle_flame.py --model runs\candle_yolo\weights\best.pt --camera 0
```

The detector requests Logitech capture at 1280x720 using MJPG, runs inference
on CUDA device 0, and displays every detected flame with its confidence,
bounding box, and center point, plus resolution and FPS. Press **Q** to close
it cleanly.

For distant flames, use the PyTorch checkpoint at a larger inference size and
optionally lower the confidence threshold. This is slower and may produce more
false positives:

```powershell
python detect_candle_flame.py --model runs\candle_yolo\weights\best.pt --imgsz 960 --conf 0.30 --iou 0.35 --width 1920 --height 1080 --fps 30
```

`--width` and `--height` control camera capture resolution; `--imgsz` controls
the image size passed to the model. The program prints the mode the webcam
actually accepted. The current TensorRT engine has a fixed 640x640 input, so larger `--imgsz`
values require the `.pt` checkpoint until a larger engine is exported.

Start with `--conf 0.30 --iou 0.35` in rooms containing lamps or other bright
objects. Raising `--conf` rejects weak false positives; lowering `--iou`
suppresses duplicate overlapping boxes around one flame. Lower confidence only
after testing false positives in the actual installation environment.

Its stable result fields are:

```text
flame_detected, flame_confirmed, flame_count, confidence, bounding_box,
center_x, center_y, detections
```

`detections` contains every flame found in the frame. The scalar confidence,
box, and center fields continue to describe the strongest flame for compatible
future pan/tilt code.

`flame_confirmed` becomes true only after flame detections in three consecutive
frames. `latest_detection` exposes the most recent result for later pan/tilt
localization. This test never sends commands to the pump or ESP32.

## Collect targeted improvement data

The model needs hard-negative images of the actual room lights and positive
images at the intended operating distances. Never mix nearly identical frames
across train, validation, and test splits.

With no flame visible, collect varied room-light views as empty-label negative
examples. Press **Space** to save and **Q** to quit:

```powershell
python collect_candle_training_data.py --mode negative --camera 0
```

Collect distant and multi-flame positives with the same camera. Press **Space**
to freeze a frame, drag one tight box around each separate flame, then press
**S** to save. Press **U** to undo the last box, **C** to discard the frozen
frame, and **Q** to quit:

```powershell
python collect_candle_training_data.py --mode positive --camera 0
```

For multi-flame scenes, every visible flame must have its own box. Do not label
the combined area around several flames as one object. Capture different
distances, camera angles, brightness levels, backgrounds, and times of day.

## Public-data fine-tuning

`import_public_dfire.py` imports D-Fire records from downloaded Hugging Face
Parquet shards. It retains only `fire` boxes as class `0 = flame`, creates empty
labels for selected no-fire and smoke-only negatives, and writes
`datasets/candle-fire-enhanced.yaml` without modifying the original candle
dataset. D-Fire is released under CC0; the processed Hugging Face mirror is
published under CC BY 4.0, so retain source attribution.

The robust profile simulates camera and scene variation with scale, exposure,
color, viewpoint, mosaic, and mixup augmentation while continuing from the
existing candle checkpoint:

```powershell
python train_candle_yolo_cuda.py `
  --data datasets\candle-fire-enhanced.yaml `
  --model runs\candle_yolo\weights\best.pt `
  --batch 1 --imgsz 960 --epochs 120 --patience 25 `
  --augmentation robust --name candle_yolo_public_960
```

For a higher-resolution retraining run after adding more distant and
multi-flame images:

```powershell
python train_candle_yolo_cuda.py --batch 1 --imgsz 960 --epochs 150 --patience 30 --name candle_yolo_960
```

## TensorRT FP16 export

After training:

```powershell
python export_tensorrt.py
```

This exports `best.pt` for CUDA device 0 at image size 640 and batch size 1.
Current Ultralytics uses `quantize=16` for FP16 TensorRT export. The generated
`best.engine` is GPU/TensorRT-environment-specific and is ignored by Git.

## Safety

Use simulated targets for development. Pump control must remain off. Person
detection and the no-spray decision are a separate safety layer and must be
validated before any complete suppression system is operated.
