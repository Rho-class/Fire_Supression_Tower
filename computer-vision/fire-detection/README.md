# Candle Flame Detection

This folder trains and runs a dedicated one-class YOLO26 detector. Its only
class is `0 = flame`. It does not control the pump, motors, or ESP32, and it
does not perform person detection. Those responsibilities remain separate.

## Running on another laptop

Needs Windows, an NVIDIA GPU (the C270 detector refuses to start without CUDA),
Python 3.14, and [Git LFS](https://git-lfs.com) for the model.

```powershell
git lfs install
git clone https://github.com/Rho-class/Fire_Supression_Tower.git
cd Fire_Supression_Tower\computer-vision\fire-detection
py -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe .\detect_candle_flame_c270.py --motors --port COM5 --camera 1
```

If the repo is already cloned, run `git pull` then `git lfs pull`. Check Device
Manager for the ESP32's COM port and change `--port` to match; if the wrong
camera opens, try `--camera 0`. The trained model is in the repo. Datasets and
recorded videos are not, so retraining needs them copied over separately.

## Environment and CUDA

Use the project virtual environment from PowerShell:

```powershell
cd computer-vision\fire-detection
.\.venv\Scripts\Activate.ps1
```

Install a CUDA-enabled PyTorch build using the command generated by the
[official PyTorch Windows selector](https://pytorch.org/get-started/locally/).
Install the remaining packages afterward:

```powershell
python -m pip install -r requirements.txt
```

The OpenCV requirement remains pinned to `4.14.0.94` to avoid an unintended
OpenCV replacement. Verify the driver and PyTorch before doing anything else:

```powershell
nvidia-smi
python -c "import torch; print('PyTorch:', torch.__version__); print('CUDA available:', torch.cuda.is_available()); print('CUDA:', torch.version.cuda); print('GPU:', torch.cuda.get_device_name(0) if torch.cuda.is_available() else 'None')"
```

Do not train if `CUDA available` is `False`. All three production scripts also
enforce this and will not silently fall back to CPU.

## Dataset

Download the candle-fire dataset in **YOLO26** format from:

<https://universe.roboflow.com/processing-workspace/candle-fire-mz13q>

Extract it so the configuration is located here:

```text
computer-vision/fire-detection/datasets/candle-fire/data.yaml
```

Before training, inspect `data.yaml`. It must contain exactly one class and
working `train` and `val` paths. The training script verifies those paths and
writes a generated configuration that normalizes the class to `0 = flame`.
The downloaded dataset and generated configuration are ignored by Git.

Future Logitech-camera training images should include small candle flames at
about 5 feet and, where practical, 10 feet. Add hard-negative images of
flashlights, red/orange objects, desk lamps, reflections, unlit candles, and
phone screens. A negative image must have a matching empty YOLO label file.

## Training

```powershell
python train_candle_yolo_cuda.py
```

Training starts from `yolo26x.pt`, uses CUDA device 0, 640-pixel images,
automatic CUDA batch sizing, mixed precision, up to 100 epochs, and early
stopping after 20 epochs without improvement. The first run normally writes:

```text
runs/candle_yolo/weights/best.pt
```

Ultralytics adds a numeric suffix for later runs rather than overwriting an
existing run. Pass the desired checkpoint to the other scripts with `--model`.

On an 8 GB RTX 5060, Ultralytics' automatic profiler may discover batch 2 but
then leave CUDA in an out-of-memory state while probing larger candidates. If
that happens, restart training with the discovered safe value:

```powershell
python train_candle_yolo_cuda.py --batch 2
```

## C270 two-stage detector (5–10 ft, current)

For candle detection at 5–10 ft, use the Logitech C270 and
`detect_candle_flame_c270.py`. It runs autonomously with no setup keys:
manual exposure −7 and automatic white balance, a bright-spot finder, a colour
gate that rejects room lights (they render neutral/blue; a candle renders
orange), a YOLO check for near flames, a spot rule for far flames, and the
existing 5-frame tracker with simulated pan/tilt output. The Acer WBC-0E01
cannot set exposure, so distant flames clip to white and are not detected
reliably.

```powershell
.\.venv\Scripts\python.exe .\detect_candle_flame_c270.py                  # autonomous
.\.venv\Scripts\python.exe .\detect_candle_flame_c270.py --guided         # distance test
.\.venv\Scripts\python.exe .\detect_candle_flame_c270.py --pan-tilt-test  # aiming test
.\.venv\Scripts\python.exe .\detect_candle_flame_c270.py --motors --port COM5  # live motors
```

### Indoor / outdoor mode

Press **O** while running to switch modes (or start with `--mode outdoor`).

- **Indoor** (default): the tested settings above, exposure −7. Unchanged.
- **Outdoor**: auto exposure for daylight. Every ~0.3 s it shortens exposure one
  step if more than 0.5% of the frame clips to white (sky, glare) and lengthens
  it if the scene is dark, between −13 and −7. **A** turns auto exposure off/on;
  `[` / `]` set it by hand. Detection thresholds start equal to indoor and are
  being tuned from outdoor recordings.

Outdoor tuning session (record raw video for offline re-tuning):

```powershell
.\.venv\Scripts\python.exe .\detect_candle_flame_c270.py --mode outdoor --guided --record
```

Each run writes `runs/c270-live/session_<time>.csv` and, with `--record`,
`session_<time>.mp4`; CSV column `frame` is the video frame number. The CSV
also logs `mode` and `exposure` per frame.

Re-grade a recording with the current (or trial) settings, no camera needed:

```powershell
.\.venv\Scripts\python.exe .\replay_c270_session.py runs\c270-live\session_20261106_161827 --mode outdoor
.\.venv\Scripts\python.exe .\replay_c270_session.py <session> --mode outdoor --spot-min-contrast 150
```

Outdoor differs from indoor only in the far-flame spot rule (`OUTDOOR_SPOT_*`
in `detect_candle_flame_c270.py`): aspect ≥ 0.5 instead of 1.0 (at exposure
−11 only the flame core shows, often wind-tilted and wider than tall) and
contrast ≥ 160 instead of 150 (late-sun glints on bark reached 134; the candle
never fell below 174).

### Search sweep (`--motors`)

With nothing in view for 3 s, the pan sweeps back and forth between the
firmware's ±45° soft limits (about 8°/s, reversing on each `LIMIT pan` reply)
until a flame candidate appears; then it stops so the flame can be confirmed
and tracked. **P** turns the sweep off/on. It also pauses while the pump is on.

**Startup tilt:** every run (with `--motors`) first tilts the camera
`STARTUP_TILT_DOWN_DEG` (15° down) and makes that straight ahead and level
(firmware `Z`), then the pan sweep starts looking for a flame. Use
`--no-level` when the head is already straight; **L** twice redoes it.

When a tracked flame has been gone for 5 s and the pump is off, the head resets
straight ahead and level (firmware `C`); the sweep waits for that reset and
resumes 1.5 s later (`HOME_AFTER_LOST_S`, `SWEEP_AFTER_HOME_S` in `config.py`). Don't use **L** for this: L
only undoes the hose sag right after the 12 V is turned on.

### Water-arc aiming (`aim.py`)

While the pump is on, the head tilts up by the low-arc launch angle for the
flame's distance, so the stream lands on the flame instead of dropping short.
The overlay shows `~D ft (set | size est.)  aim +X deg` and a magenta
**water aim** marker where the flame is held while spraying.

1. **Measure the nozzle speed once:** spray *level* from height H (m), measure
   where the water lands, R (m), then
   `.\.venv\Scripts\python.exe .\aim.py --height H --range R` and copy the
   printed `NOZZLE_SPEED_MPS` into `config.py` (aiming stays off until set).
2. **Distance:** press **5 / 7 / 0** (5, 7.5, 10 ft) to set it. Without that it
   falls back to an estimate from the flame's size (`h = a + b/d`, fitted to
   the tagged sessions; typically within ~0-2.5 ft) clamped to 5-10 ft, so the
   aim never goes beyond 5.1-10.4°. Candle size varies, so set it when you can.
3. **Autonomous firing** (`autofire.py`, SPACE arms / disarms): when the flame
   has been CENTERED on the crosshair for 1 s, the head moves to the aim point
   (the arc angle up, `AIM_LEFT_DEG` left; 7.5 ft assumed without a size
   estimate) and the pump sprays one burst: the tilt sweeps up and down ±4°
   through the aim point (up, down, up: 3 s), with no self-correcting. Then pump off, back onto the flame, 1 s to
   look again; if it still burns it re-centres, locks and fires again.
   Water: each burst is counted against a per-trial share (half a gallon / 5
   trials = 378 mL at `PUMP_FLOW_ML_S`, an estimate until measured); once used
   it stops firing until the flame is out and the head has gone home.

Assumes the nozzle sits at the camera and the flame is about level with it.

With `--motors`, **Space** arms / disarms auto-fire (it never fires on its
own). Q turns it off before closing, and the firmware also cuts it after 1.5 s
without commands, so a crashed laptop cannot leave it running.

Design, measurements, live results, and limitations are in
`docs/Fire_Suppression_Tower_Technical_Appendix.md`, Section K.

## Webcam detection

The default model preference is `best.engine`, followed by `best.pt`:

```powershell
python detect_candle_flame.py
python detect_candle_flame.py --model runs\candle_yolo\weights\best.pt --camera 0
```

The detector requests Logitech capture at 1280x720 using MJPG, runs inference
on CUDA device 0, and displays every detected flame with its confidence,
bounding box, and center point, plus resolution and FPS. Press **Q** to close
it cleanly.

For distant flames, use the PyTorch checkpoint at a larger inference size and
optionally lower the confidence threshold. This is slower and may produce more
false positives:

```powershell
python detect_candle_flame.py --model runs\candle_yolo\weights\best.pt --imgsz 960 --conf 0.30 --iou 0.35 --width 1920 --height 1080 --fps 30
```

`--width` and `--height` control camera capture resolution; `--imgsz` controls
the image size passed to the model. The program prints the mode the webcam
actually accepted. The current TensorRT engine has a fixed 640x640 input, so larger `--imgsz`
values require the `.pt` checkpoint until a larger engine is exported.

Start with `--conf 0.30 --iou 0.35` in rooms containing lamps or other bright
objects. Raising `--conf` rejects weak false positives; lowering `--iou`
suppresses duplicate overlapping boxes around one flame. Lower confidence only
after testing false positives in the actual installation environment.

Its stable result fields are:

```text
flame_detected, flame_confirmed, flame_count, confidence, bounding_box,
center_x, center_y, detections
```

`detections` contains every flame found in the frame. The scalar confidence,
box, and center fields continue to describe the strongest flame for compatible
future pan/tilt code.

`flame_confirmed` becomes true only after flame detections in three consecutive
frames. `latest_detection` exposes the most recent result for later pan/tilt
localization. This test never sends commands to the pump or ESP32.

## Collect targeted improvement data

The model needs hard-negative images of the actual room lights and positive
images at the intended operating distances. Never mix nearly identical frames
across train, validation, and test splits.

With no flame visible, collect varied room-light views as empty-label negative
examples. Press **Space** to save and **Q** to quit:

```powershell
python collect_candle_training_data.py --mode negative --camera 0
```

Collect distant and multi-flame positives with the same camera. Press **Space**
to freeze a frame, drag one tight box around each separate flame, then press
**S** to save. Press **U** to undo the last box, **C** to discard the frozen
frame, and **Q** to quit:

```powershell
python collect_candle_training_data.py --mode positive --camera 0
```

For multi-flame scenes, every visible flame must have its own box. Do not label
the combined area around several flames as one object. Capture different
distances, camera angles, brightness levels, backgrounds, and times of day.

## Public-data fine-tuning

`import_public_dfire.py` imports D-Fire records from downloaded Hugging Face
Parquet shards. It retains only `fire` boxes as class `0 = flame`, creates empty
labels for selected no-fire and smoke-only negatives, and writes
`datasets/candle-fire-enhanced.yaml` without modifying the original candle
dataset. D-Fire is released under CC0; the processed Hugging Face mirror is
published under CC BY 4.0, so retain source attribution.

The robust profile simulates camera and scene variation with scale, exposure,
color, viewpoint, mosaic, and mixup augmentation while continuing from the
existing candle checkpoint:

```powershell
python train_candle_yolo_cuda.py `
  --data datasets\candle-fire-enhanced.yaml `
  --model runs\candle_yolo\weights\best.pt `
  --batch 1 --imgsz 960 --epochs 120 --patience 25 `
  --augmentation robust --name candle_yolo_public_960
```

For a higher-resolution retraining run after adding more distant and
multi-flame images:

```powershell
python train_candle_yolo_cuda.py --batch 1 --imgsz 960 --epochs 150 --patience 30 --name candle_yolo_960
```

## Mine hard negatives from no-flame video

Record several videos containing lamps, ceiling lights, windows, reflections,
screens, and other distractors. Each complete video is one session. Verify the
videos contain no real flame, then run the current model at a low threshold to
capture the frames it falsely classifies:

```powershell
python mine_hard_negatives.py `
  --input evaluation-videos\lamp-morning.mp4 evaluation-videos\lamp-night.mp4 `
  --model runs\candle_yolo\weights\best.pt `
  --conf 0.10 --sample-fps 2 --minimum-seconds 2 `
  --confirm-no-flame
```

The miner:

- saves full false-positive frames with matching empty YOLO label files;
- saves annotated review copies outside the training image folders;
- filters near-identical frames with a perceptual hash;
- assigns each entire video session to only one split; and
- generates `datasets/candle-kaggle-hard-negatives-mined.yaml`, which combines
  the existing flame data and hard negatives with the newly mined samples.

Inspect every image under `datasets/hard-negative-mined-v1/review/`. Delete a
training image, its matching empty label, its review copy, and its manifest row
if any real flame is visible. Never train on an incorrectly empty label.

After review, fine-tune from the current checkpoint:

```powershell
python train_candle_yolo_cuda.py `
  --data datasets\candle-kaggle-hard-negatives-mined.yaml `
  --model runs\candle_yolo\weights\best.pt `
  --batch 1 --imgsz 640 --epochs 80 --patience 20 `
  --augmentation robust --name candle_hard_negative_v2
```

Re-run `evaluate_flame_model.py` on the untouched test split after training.
Do not move mined training sessions into the test split after viewing results.

## Model evaluation

Use `evaluate_flame_model.py` to measure image-level candle recall and lamp
rejection across several confidence thresholds. Positive images must have at
least one class-0 YOLO box; lamp and other no-flame images must have matching
empty label files. Keep complete recording sessions in only one split so that
nearly identical frames cannot leak between training and evaluation.

Evaluate the held-out test split:

```powershell
python evaluate_flame_model.py images `
  --data datasets\candle-kaggle-hard-negatives.yaml `
  --split test `
  --model runs\candle_yolo\weights\best.pt `
  --thresholds 0.10,0.20,0.30,0.40,0.50,0.60,0.70,0.80,0.90
```

The evaluator writes individual image scores, threshold metrics, and a JSON
report under `runs/evaluation/`. Select a threshold using both flame recall and
false-positive rate. A displayed confidence of 0.80 is not itself evidence of
80% detection reliability. Evaluation uses batch size 1 so the YOLO26x model
fits the project's 8 GB GPU. The default acceptance target is at least 80%
recall and at most a 5% image-level false-positive rate. Override it with
`--min-recall` and `--max-fpr`, or add `--fail-on-target` for an automated test
that exits unsuccessfully when no tested threshold passes.

Record long videos with no flame visible while showing ceiling lights, lamps,
reflections, screens, and windows. Measure false confirmation events per hour:

```powershell
python evaluate_flame_model.py video `
  --input evaluation-videos\lamp-room-1.mp4 evaluation-videos\lamp-room-2.mp4 `
  --model runs\candle_yolo\weights\best.pt `
  --confirmation-frames 3
```

For a useful first acceptance target, require at least 80% recall on held-out
candle images and zero false confirmation events in the available no-flame
video. Continue recording longer and more varied video before treating the
result as a safety claim.

## ESP32 USB aiming link

By default `SIMULATION_MODE = True` in `config.py` and the detector only prints
`PAN:…,TILT:…` lines. To drive the steppers over USB:

1. Flash `firmware/` (`pio run -t upload`) and note the ESP32 COM port.
2. Set `SERIAL_PORT` (for example `COM3`) and `SIMULATION_MODE = False` in
   `config.py`.
3. Install pyserial if needed: `python -m pip install pyserial`
4. Run the detector (keep sending while a flame is tracked so the firmware jog
   timeout does not stop the motors):

```powershell
python detect_candle_flame.py --model runs\candle_yolo\weights\best.pt --camera 1 --width 1280 --height 720
```

5. Off-center flame → motors jog toward the error; centered / no flame / **Q** →
   both axes stop (`PAN:0,TILT:0`). Pump is not commanded by this link.
6. If an axis is reversed, toggle `PAN_INVERT` / `TILT_INVERT` here or
   `PAN_AXIS_INVERT` / `TILT_AXIS_INVERT` in `firmware/src/main.cpp`.

### C270 detector on the motors (recommended order)

The C270 detector drives the motors only with `--motors`; `config.py` can stay
in simulation. `SERIAL_PORT = "auto"` finds the ESP32 by its USB chip and never
picks a Bluetooth port. The firmware stops each axis at a soft travel limit
(`PAN_LIMIT_DEG` ±45°, `TILT_LIMIT_DEG` ±20° of head travel from the power-on
position) and scales tracking speed with the correction (3–25 head degrees per
second). Gear ratios are set in `firmware/src/main.cpp`: pan 8:1, tilt about
5:1 (motor turns per head turn).

1. Flash: from `firmware/`, `pio run -t upload` (ESP32 plugged in by USB).
2. Point the head straight ahead and level, then reset or power-cycle the ESP32;
   that position becomes the centre for the travel limits.
3. Bench check, no camera: `python motor_check.py`. It nudges pan left/right
   and tilt up/down slowly and prints the position. Fix any reversed axis with
   `M1_INVERT_DIRECTION` / `M2_INVERT_DIRECTION` in `firmware/src/main.cpp`.
4. Track: `python detect_candle_flame_c270.py --motors`. The status bar shows
   `MOTORS LIVE on COMx`; **Q** stops both axes. Start with the candle near the
   centre of view and a hand near the motor power switch.

## Safety

Use simulated targets for development. Keep `SIMULATION_MODE = True` until the
ESP32 link is intentionally enabled. Pump control must remain off for vision
tests. Person detection and the no-spray decision are a separate safety layer
and must be validated before any complete suppression system is operated.
